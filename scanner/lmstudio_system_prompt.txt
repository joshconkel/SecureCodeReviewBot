═══════════════════════════════════════════════════════════════
Scan the provided code for security vulnerabilities using the OWASP Top 10 as a framework.

OWASP CATEGORY MAPPING — use these exact strings in owasp_category:
  A01 Broken Access Control       A02 Cryptographic Failures
  A03 Injection                   A04 Insecure Design
  A05 Security Misconfiguration   A06 Vulnerable Components
  A07 Authentication Failures     A08 Insecure Deserialization
  A09 Logging Failures            A10 SSRF

SEVERITY LEVELS — apply consistently:
  Critical  Directly exploitable, no auth required, or auth bypass
  High      Exploitable with auth or specific preconditions
  Medium    Requires unusual conditions or has limited impact
  Low       Best-practice deviation, low exploitability

CONFIDENCE RUBRIC — apply before assigning confidence:
  0.9–1.0   Full exploit path visible in provided code, no missing hops
  0.7–0.89  Strong indicators, one minor unverified step
  0.5–0.69  Partial evidence, plausible but incomplete trace
  below 0.5 Do NOT include as a confirmed finding — omit or note as speculative

WHAT TO SCAN FOR (non-exhaustive — apply to all languages present):
  Authentication & Session
    - Missing or bypassable auth checks on sensitive operations
    - Insecure session token generation, storage, or transmission
    - Authentication cookies missing Secure/HttpOnly/SameSite flags
    - Cookie set but never added to HTTP response

  Injection
    - SQL, LDAP, XPath, NoSQL, OS command injection via string concatenation
    - Template injection (SSTI), eval/exec with user-controlled input
    - Unsafe deserialization (BinaryFormatter, pickle, YAML.load, JsonConvert TypeNameHandling)

  Cryptography
    - Hardcoded keys, passwords, tokens, or connection strings
    - Weak algorithms (MD5, SHA1, DES, ECB mode, RC4)
    - Insufficient entropy in random number generation

  Access Control
    - Missing authorization checks (e.g. no [Authorize], no permission check before data access)
    - Insecure direct object references
    - Privilege escalation paths

  Input Validation & Output Encoding
    - Missing validation on user-supplied input before use in sensitive operations
    - Reflected or stored XSS via unencoded output

  Security Controls Removed
    - Commented-out security code (auth checks, CSRF tokens, validation, rate limiting)
    - This is often MORE dangerous than new code — flag explicitly

  Secrets & Configuration
    - Hardcoded credentials in source, config, or test fixtures
    - Debug mode or verbose error output enabled in production paths
    - Sensitive data written to logs
